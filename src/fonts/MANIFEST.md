# Vendored math fonts

Generated by `scripts/fonts.py` (`uv run scripts/fonts.py`). Do not edit by hand;
re-run the script instead. It is idempotent -- cached originals are verified by
SHA-256 and reused, and the outputs are rewritten deterministically.

Every font here is the **unmodified upstream font**: no glyph subsetting, no
`name` table edits, no re-hinting, no metadata injection. Coverage of
U+1D400-1D7FF (Mathematical Alphanumeric Symbols) is mandatory for MathML Core,
whose UA stylesheet maps single-character `<mi>` into that block via
`text-transform: math-auto`.

#### On the GFL renaming request

Clause 1 of the GUST Font License asks -- _"it is requested, but not legally
required"_ -- that derived works rename both the fonts and the files listed in
the upstream `MANIFEST-Latin-Modern-Math.txt`. That manifest lists the OTF menu
names `Latin Modern Math` and `LatinModernMath-Regular` (§1.1) and the file
`otf/latinmodern-math.otf` (§2.1).

The **file** is renamed (`latin-modern-math.woff2`). The **menu names are
deliberately kept**, and this is a disclosed departure from a request the
license itself marks as non-binding:

- The conversion is functionally equivalent to the original in the OFL-FAQ
  2.7/2.8 sense -- same outlines, same metrics, same MATH table, same `name`
  records. A renamed family would misrepresent a font that is byte-for-byte
  equivalent in every table as something different.
- Browsers keep hardcoded lists of math family names for MathML font handling.
  Renaming the family opts it out of those lists, and the `math` generic cannot
  see `@font-face` in Gecko or Chromium, so there is no way to opt back in.

A **glyph subset** would be a different matter -- see `scripts/fonts.py
--subset`, which refuses to write into this directory for exactly that reason.
