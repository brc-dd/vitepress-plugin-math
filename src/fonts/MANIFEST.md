# Vendored math fonts: provenance and license notices

Generated by `scripts/fonts.py` (`uv run scripts/fonts.py`). Do not edit by hand;
re-run the script instead. It is idempotent -- cached originals are verified by
SHA-256 and reused, and the outputs are rewritten deterministically.

This directory redistributes third-party font software. **The fonts are not
covered by this package's MIT license.** Each is governed by the license
distributed beside it here, and those terms travel with the files into
`dist/fonts/` and into the published tarball. `ACKNOWLEDGEMENTS.md` at the
repository root is the package's notice register and points back to this file.

Neither font is subsetted. Both retain full coverage of U+1D400-1D7FF
(Mathematical Alphanumeric Symbols), which MathML Core makes mandatory: its UA
stylesheet maps every single-character `<mi>` into that block via
`text-transform: math-auto`. A glyph subset would be a modified version of the
font under both licenses below; nothing here is one.

#### GFL clause 1: the renaming request

Clause 1 of the GUST Font License states that it is _"requested, but not
legally required"_ that derived works rename both the fonts and the files
listed in the accompanying manifest. Upstream's
`doc/MANIFEST-Latin-Modern-Math.txt` lists, expressly under clause 1, the OTF
menu names `Latin Modern Math` and `LatinModernMath-Regular` (§1.1) and the
file `otf/latinmodern-math.otf` (§2.1).

The **file** is renamed, to `latin-modern-math.woff2`, honoring §2.1. The
**menu names are deliberately kept**. That is a disclosed departure from a
request the license itself marks as non-binding, and it is recorded here so
the departure is on the record rather than silent:

- The conversion is functionally equivalent to the original in the OFL-FAQ
  2.7/2.8 sense -- same outlines, same metrics, same MATH table, same `name`
  records. Renaming the family would represent a font whose every table is
  identical to upstream's as though it were a different typeface.
- Browsers keep hardcoded lists of math family names for MathML font handling.
  Renaming the family opts it out of those lists, and the `math` generic cannot
  see `@font-face` in Gecko or Chromium, so there is no way to opt back in.

No provision of the GFL or of LPPL 1.3c is waived by this. A **glyph subset**
would be a different matter -- see `scripts/fonts.py --subset`, which refuses
to write into this directory for exactly that reason.
